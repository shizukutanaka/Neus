# SONNET.md — Neus 広さレビュー指示書(Sonnet)

まず `AUDIT-BRIEF.md` を読む。あなたは独立レビュアー。`OPUS.md` の出力は見ない(独立性を保つ)。
製品全体を走査するが、**主レンズは「広さ」** — 一次元ずつ機械的に網羅し、抜け漏れを潰す。各指摘は
再現を確認してから報告する。

## 主対象(広さ。1次元ずつ順に)

1. **UX / Apple HIG**: 視線フロー 見→比較→行動 が3ステップ以内か。CTA/focus/ブランド以外に
   `#00C4CC` を使っていないか。絵文字混入ゼロ。空状態 / ローディング / エラーの提示。
2. **アクセシビリティ**: `check-html.mjs` の不変条件(全 modal に `role=dialog`+`aria-modal`、
   `focus-visible` の 3px outline、`search-input` の `aria-label`、`toast` `role=status`、
   `prefers-reduced-motion`)。フォーカストラップ / 復元、キーボード操作パリティ、コントラスト。
3. **i18n JA/EN 一貫性**: 単一言語のトースト / ラベル残り、同一機能の成功/失敗で言語が食い違う組、
   ハードコード文言。`DICT` キーと `t()` 経由の網羅(round 29 の系統的スイープの継続)。
4. **テスト網羅ギャップ**: 新規/変更コードに対応するテストの有無、境界値・エラー経路の欠落、
   文字列アンカーの陳腐化。
5. **性能 / INP**: 全件スキャンの yield、初回描画順序、不要な再レンダー、SW キャッシュ肥大。
6. **ドキュメント整合**: README / SPEC / CHANGELOG / ADR / DEPLOY のバージョン・参照の食い違い、
   実在しないファイル / 機能への言及。

## 手法

- 上記 1→6 を順に、各次元で網羅的に。飛ばした範囲があれば明記(silent truncation を作らない)。
- 各指摘は実際に再現(該当 DOM / コード / フローを確認)してから報告。
- 拡散的だが機械的な修正(i18n 統一、aria 追加等)は `AUDIT-BRIEF` §1 の規律下でまとめて提案。

## 制約

- `AUDIT-BRIEF` §0 のゲートに触れる改善は**実装せず ADR ドラフトまで**。
- §3 の長所は再修正しない。§2 の却下案は再提案しない。
- ソース変更時は文字列アンカーテスト更新・CSP 再生成(`build:csp`)・`lint:html` を必ず通す。

## 出力

`AUDIT-BRIEF` §5 のフォーマット。最後に「独立レビュー: 他レビュアーの出力は未参照」と明記。
記録先は `AUDIT-BRIEF` §4。
