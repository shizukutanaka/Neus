# ADR-0012 — InterestProfile: 行動学習による暗黙の情報選別

**Date**: 2026-05-30
**Status**: ACCEPTED (v0.5.0で実装)

## Context

「欲しい情報/いらない情報を的確に選ぶ」仕組みが課題。既存の選別機構を棚卸しすると:

| 機構 | 仕組み | 限界 |
|---|---|---|
| KeywordRules | 明示ルール(WATCH/BLOCK) | ユーザーが手動で語を登録する必要 |
| TagLearner | ユーザーのタグ付けを学習 | タグ付けしないと機能しない |
| recencyBoost | 時間減衰 | 興味と無関係 |
| score | 固定初期値 + ルール加点 | 行動を学習しない |

**核心的欠落**: star/archive という最も強い興味シグナルが、今後の選別に一切フィードバックされていなかった。明示操作(キーワード登録)なしに行動から「欲しい/いらない」を学習する仕組みがない。

## Decision

**InterestProfile** モジュールを新設。star/archive の行動から語彙の極性を学習し、新着イベントのスコアを暗黙に±補正する。

## Design

### 学習(Rocchio/ナイーブベイズ的)
- star した記事の特徴語 → positive カウント+1(欲しい情報のシグナル)
- archive した記事の特徴語 → negative カウント+1(いらない情報のシグナル)
- undo(unstar/unarchive)時は sign=-1 で打ち消し
- 特徴語 = title + snippet + userTags + autoTags のトークン

### スコアリング
新着イベントの各語について:
- 語の極性 = (pos - neg) / (pos + neg) ∈ [-1, 1]
- 学習サンプル数 < `interestMinDf`(=2)の語は無視(ノイズ除去)
- boost = round(平均極性 × `interestBoostMax`(=25))
- event.stored で `meta.score` に加算(0〜100にクランプ)

### 忘却
- 語彙が `interestMaxVocab`(=300)超過時、極性絶対値の低い語から削除
- 興味の変化に追従

### プライバシー(ADR-0011の優位を維持)
- 全処理ローカル・IndexedDB保存のみ。サーバー送信ゼロ
- 連合学習/差分プライバシーが原理的に不要(送信しないため)

### 可視化
- STATSモーダルに「好み(自動学習)」「除外(自動学習)」のtop語を表示
- ユーザーが何が学習されたかを確認・透明性を担保

## Rationale

### なぜ明示(KeywordRules)と別に暗黙学習が要るか
- 明示ルールはユーザーの能動的操作が前提 → 多くのユーザーは設定しない
- star/archive は自然な操作で、最も信頼できる興味シグナル
- 明示(優先)+ 暗黙(補助)の二層で「的確な選別」を実現

### なぜRocchioでなくニューラルNNでないか
- ゼロ依存・ローカル制約。NNはモデルサイズ・学習コストで不適
- 語の極性カウントは O(語数) で軽量・解釈可能(透明性)
- arXiv調査(ADR-0010/0011)でもオンデバイスはシンプルな手法が適すると確認

## Consequences

- **+**: 明示操作なしに「欲しい/いらない」を学習、新着の優先度に反映
- **+**: KeywordRules(明示)と相補。両方が効く
- **+**: 完全ローカル・透明(STATSで可視化)・解釈可能
- **+**: undo対応で誤操作に強い
- **-**: コールドスタート(初回は学習データなし→boost 0)。ただし使うほど精度向上
- **-**: 語ベースなので同義語・文脈は捉えない(embeddingはADR-0006のv1.1領域)
